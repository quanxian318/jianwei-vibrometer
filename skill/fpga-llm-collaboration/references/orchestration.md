# 从需求到证据的协作流程

| 环节 | 给模型的输入 | 调用或产物 | 转下一步的条件 |
|---|---|---|---|
| 固定基线 | 当前 SHA、已有日志、样例数据、器件和工具链 | git rev-parse HEAD、git status --short、工具版本、固定测试向量 | 队友能找到同一份输入和原始结果 |
| 建接口 | 软件算法、RTL/HLS、BD、寄存器表 | 生成契约及正负向验收用例，逐项核对 IP 路径和字节偏移 | 软硬件对 dtype、长度、帧尾、错误处理有相同解释 |
| 核验证 | 固定输入、黄金输出、第一处错误 | 运行参考实现、RTL 仿真或 HLS C/RTL 协同仿真 | 边界向量通过，记录首个失败或通过的具体范围 |
| 构建 | 可复现 Tcl、XDC、IP 与版本 | Vivado 批处理、时序和资源报告，记录输出哈希 | 使用实际实现报告，确认约束覆盖和交付件来自同一构建 |
| 上板 | 设备、镜像、Overlay、允许的操作 | SSH 或 Notebook、寄存器、DMA、ILA | 正确性、异常恢复和端到端耗时分别留证 |
| 复盘 | 原始输出、首个反例、模型旧回答 | 用证据模板记录反证、修正和复测 | 队友能判断适用范围和失效条件 |

**跨工具诊断示例。** 板端 S2MM 超时，先让模型说明现有证据能排除什么。用同长度 loopback 检验 DMA 链路，用软件黄金向量复跑 RTL，随后 ILA 检查 TLAST 是否在最后一个成功握手出现。如果短包通过而长包失败，将长度、DRE、帧尾和软件超时作为独立变量，逐项更改。报告保存原始命令、退出码和抓到的第一处差异。此示例用于指导复用，真实协作轨迹另按项目案例记录。

**交接单示例。** 任务 ID、源码 SHA、目标板、输入及哈希、期望与实际结果、工具调用和日志、第一处差异、修正、复测、待补验证。下一位操作者从失败复现或证据缺口开始，模型回答中缺失的实测数值保持空白。
